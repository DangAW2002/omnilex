# ADR 0002: Claude Code Mod Adapter Architecture

## Status
Accepted

## Context
AI agents often emit specialized jargon when answering users. Users may be intimidated by unfamiliar vocabulary or misunderstand nuances. Standard solutions require:
1. Teaching the model via prompt instructions to annotate terms (wastes token context and slows output).
2. Querying external API tools mid-generation (introduces latency and network failure modes).

## Decision
We implement a client-side terminal adapter (`packages/claude-mod`) that intercepts assistant response rendering on the client terminal:
1. The mod loads pre-compiled `terms.json` (generated by `tb build`) into local memory upon startup.
2. Hook `ui.render` scans plain text in `AssistantMessage`, skipping code blocks and URLs.
3. Matching terminology is converted into pressable links with an interactive side pane showing plain explanation, examples, and distinctions.

## Consequences
### Positive
- Zero LLM tokens consumed for term explanations.
- Zero network latency during streaming; lookups occur in microseconds via local dictionary.
- Fully decoupled: LLM remains unaware of the mod.

### Tradeoffs
- Limited to Claude Code CLI and Desktop Code tab where `ui.render` hooks are supported.
- Requires maintenance of `terms.json` build artifact.
